# Mori 0.1.2 手动检查

2026-10-13，在 Apple Silicon Mac、macOS 27.0 上通过原生应用界面实际点击、输入、保存与重启。使用独立的 Mori Documentation 应用副本、设置域与临时文章目录；未读取或修改用户自己的文章、设置与已安装应用。

## 已复现并修复的问题

| 操作 | 修复前现象 | 修复后复验 |
| --- | --- | --- |
| 森林背景下鼠标点击主题卡片和选择图片 | 没有响应；通过辅助功能按钮动作却能切换 | 普通鼠标点击 Night、Paper 和卡片空白处均有效；选择图片打开文件对话框 |
| 外观页滚到底部，再切到文字页 | 沿用原滚动位置，字体入口不可见 | 字体菜单与标题立即出现在顶部 |
| 设置中导入无效主题 JSON | 提示被设置窗口挡住，要先关设置才能看见 | 提示直接出现在设置窗口上方，关闭提示后仍能继续设置 |
| 新建 Astro 博客后立即输入 | 文本插到文章标题开头 | 标题保留，第一段进入正文 |
| 从写作切到源码后直接输入 | 隐藏的富文本编辑器仍接收输入，文字顺序异常 | 源码获得焦点，`MODE_CHECK` 顺序正确；分栏输入更新预览，回写作后输入也正常 |
| 富文本查找替换输入小写词 | 自动更正把替换词首字母改为大写 | `Paragraph` 替换成 `paragraph`，正文与替换框均保留小写 |
| 导出 PDF | 应用卡住，临时 PDF 持续膨胀 | 短文章 1 页、17,514 字节；示例博客 2 页、38,971 字节；页面约 595 × 842 pt，正文可提取，应用继续响应 |
| 导出 HTML | 文章与公式样式没有完整带入 | 文章样式、KaTeX 样式和 60 处字体数据已嵌入，无剩余相对字体路径，首尾正文保留 |
